# Планировщик крафта (`craft.py`)

Задача: по цели (какие моды, какого тира, какие обязательны, какие «N из группы») найти последовательность действий
с наименьшей **средней** стоимостью в divine по текущим ценам poe.ninja, показать её как гайд и вести игрока
пошагово. Всё случайное разыгрывается Монте-Карло (тысячи виртуальных крафтов на стратегию).

## Поток данных
```
POST /api/craft (server.run_craft)
  ├─ worker craftData(base, ilvl)       → cd: pool, desPool, marksmanPool, lords, essences, alloys, tags, импликиты…
  ├─ craft_ninja(league)                → цены (div) и иконки
  ├─ expand_pseudo()                     → псевдо-цели («total res ≥ 75», «2 пустых префикса») в обычные
  ├─ Problem(cd, targets, prices, …)     → нормализованная цель: T (моды), need_by (группы Count), capP/capS
  └─ plan_auto(prob) → summarize() + chances() → JSON для страницы
```
`implied_quality()` угадывает качество, если значения целей выше топ-тира (каталисты), — поле качества в UI нет.

## Основные сущности
- **`Pool`** — веса модов одной стороны (префикс/суффикс) для «пола» уровня (Greater/Perfect валюта катает моды
  уровня ≥ 35/50, Transmute/Augment Greater/Perfect ≥ 44/70; таблица `gamedata.FLOOR`). `W(group, side, floor, minLevel)`
  — вес нужного тира, `T(side, floor)` — сумма. Веса: `mod_weights.json` (poe2db), для модов без веса —
  средний опубликованный вес того же ранга (`rank_weights`). Ручные веса — `gamedata.WEIGHT_OVERRIDE` (id тира → вес,
  важнее poe2db и оценки): +2 к уровню снарядных скиллов (Kolr's Hunt) = 200 — со слов пользователя, 23.11.2026.
- **`M`** — мод на предмете: сторона `s`, группа `g`, номер цели `t` (−1 = мусор), флаги `fr` фрактур, `cr` крафт,
  `de` десекрейт, `un` нераскрытая кость, `lv` уровень тира. **`It`** — предмет: список `M` + редкость.
- **`Problem`** — цель пользователя. Методы:
  - `assignments()` — варианты распределения ролей: какой мод **десекрейтить**, какой **фрактурить** (3 самых редких по
    слэму: лёгкий для слэма мод бывает дёшево поймать на синем — T1-флаты Perfect Transmute), какие делать **эссенцией/Alloy**;
  - `subsets()` / `_subsets_multi()` — для групп Count: конкретные наборы модов по разбиениям префикс/суффикс
    (2+2, 1+3…). Любой мод пула той же стороны засчитывается вместо выбранного (`Ctx.pool_alias`);
  - `ctx(a)` — собрать `Ctx` под распределение.
- **`Ctx`** — всё для симуляции одного распределения: цели (`targets` с `src` = natural/desecrated/essence/alloy,
  `frac`, `opt`), пулы, цены, лимиты (`max`, `max_c`), руны, алиасы пула, `tval(t)` — во что обойдётся вернуть
  мод, если его снимет чистка (для выбора «Annul с оменом или без»).
- `Sim.precious(m)`: нужный мод, который стоит беречь от Chaos, — не фрактур, не крафт-мод и не мод, который план всё равно
  ставит эссенцией/Alloy (выпал сам — дёшево поставить заново). Только такие мешают Chaos-спаму (`cslam`/`crepair`).
- Порядок строк гайда: `Sim._pos` — место шага внутри своей попытки (новая база = новая попытка), а не первое появление в
  крафте; иначе ветка, впервые случившаяся на 2-й базе (Perfect Regal, «Добить до 3 модов»), вставала после фрактура.
- `Sim.dedup()` (в начале каждого шага): два мода на один нужный слот (закреплённый огонь + молния под «любой T1-флат») — второй считается мусором, иначе его защита превращает дешёвый Chaos/Annul в циклы с оменами.
- **`Sim`** — один виртуальный крафт по стратегии `v` (dict). `run()` — главный цикл; `pay()` — учёт валюты по
  шагам; в пошаговом режиме (`ia=True`) случайные исходы заменяются вопросами игроку (`ask()` бросает `Ask`, ответы
  передаются заново — `step_mode()` переигрывает крафт с начала с ответами).

## Стратегия `v` (ключи)
| Ключ | Смысл |
|---|---|
| `first`, `fget`, `fmode` | какой мод ловить первым на синем; как (`chaos`, Transmute/Augment `""/Greater/Perfect`, `annul:<q>` — одна база + Annul); фрактур: `four` (4 мода), `bone` (3 мода + кость), `none` |
| `facc` | что принимать на первом шаге: `only`, `hard` (не легче запланированного), `swap` (и мод десекрейт-роли — роли меняются), `pool` |
| `keep` | оставлять синий: 1 — только с первым модом, 2 — с первым или двумя нужными, 3 — с первым и ещё одним |
| `restart` | брать новую базу вместо чистки, пока нужных модов меньше `k` |
| `slam`, `greater` | какой Exalted (`""/Greater/Perfect`), Omen of Greater Exaltation |
| `fix` | чистка: `plain` Annul, `omen` Annul + омен стороны, `value` — что дешевле с учётом риска, `whittle` |
| `cw` | когда ставить крафт-моды: `first`, `junk` (вместо промаха слэма), `gamble` (Exalted на сторону без нужных, промах заменить), `last` |
| `cslam`, `chard`, `ctrim` | Chaos вместо Exalted после фрактура (качество Chaos; только самый редкий; сначала Annul до одного мусора) |
| `wfix` | перед рискованным крафт-модом снять мусор Chaos + Omen of Whittling — только если на другой стороне есть место (Chaos возвращает мод; при заполненной другой стороне он ложится обратно — был бесконечный цикл по 14 div) |
| `ftrim` | первый мод Chaos-спамом (`fget` chaos): свежий редкий сначала Annul до одного мода — нужный мод придёт на почти пустой предмет, крафт-мод потом безопасно заменит мусор (идея пользователя, 23.11) |
| `crepair` | недостающий обычный мод, когда из нужного на предмете только фрактур/крафт-моды, — Chaos-спам (`chaos_until(lose_cr=True)`: крафт-мод переживает k орбов с ((n−1)/n)^(k−1), потерянный ставится заново), а не циклы Annul + Exalted. Этап «Chaos вместо Annul + Exalted» |
| `nodyn` | запретить динамическую замену слэмов на Perfect/corrupted эссенцию |
| `dslam` | **кость вместо Exalted** для самого редкого недостающего обычного мода, если десекрейт-слот свободен: `once` (промах → дальше Exalted) или `light` (промах → Annul + Omen of Light, кость снова) |
| `bone`, `echoes`, `light` | кость `Preserved`/`Ancient`, Abyssal Echoes; неудачный десекрейт снимать: `True` Annul + Omen of Light, `False` обычный Annul (может снять нужный), `"abyss"` Essence of the Abyss + Crystallisation (`Sim.undo_des`) |
| `putref`, `echo` | Omen of Putrefaction (вся база → 6 нераскрытых), политика Echoes `always`/`need` |
| `fill` | дозаполнить свободные слоты (в UI выключено) |

## Перебор (`plan_auto` → `plan` / `_plan`)
Скорость (23.11): время уходит на сами симуляции (контекст в процессы ~20 КБ, пул ×5–6 на 9 процессах). Что сделано:
- первичный отбор в заходы: 3 крафта всем → ещё 7 тем, у кого хоть один дошёл (если не доходит никто — всем) → 40 с
  отсечкой крафта дороже 10× лучшего → 100 близким к лучшему; безнадёжные варианты больше не крутят каждый крафт до `CAP`;
- `simulate(early=True)` бросает вариант: из 10 доведено ≤3, или медиана доведённых > 2.5× `ctx.stop_ref`;
- `sim_many` берёт ориентир `ctx.ref_best` (лучший результат этого `_plan`, старт — оценка отбора), режет крафты дороже
  `CAPK`=8× него; перед «Уточняю лучшие» и в `plan()` finally всё сбрасывается в inf (точные прогоны и пошаговый режим без отсечки);
- `magic_keep2` (синий с двумя нужными): шанс и вид сохранённого предмета — точная таблица `_keep2_table` (пары исходов
  «группа×тир / мусор» по весам, оба порядка), а не 400 тыс. проб на каждое задание (было до 76% времени отбора);
- «Уточняю лучшие»: лидер с подменой способа получить первый мод на 2–3 лучших с этапа «Что принимать на первом шаге»
  (`FIRST_KEYS`) — выбор первого шага делается рано на малой выборке, поздние настройки могут подойти другому.
1. **Быстрый отбор**: все распределения × 3 пресета (× способы первого мода при фрактуре), 2 прохода (50 прогонов, потом
   ещё 100 тем, кто не хуже лучшего в 2 раза). Плюс варианты без фрактура с `keep`/`restart`.
2. `putref_screen` — грубая оценка Omen of Putrefaction.
3. Финалисты (до 4): лидер + лучший вариант каждого другого семейства в пределах ×1.6; семейство = разбиение пула + какие моды делает эссенция/Alloy (грубые пресеты отбора недооценивают эссенцию: Hysteria 258 против кости 244, после подбора 88 против 96).
4. `plan(template=…)` для каждого финалиста — координатный спуск по этапам (названия видны в прогрессе):
   «Как получить первый мод», «Что принимать на первом шаге», «Какой Exalted», «Чистка и крафт-моды»,
   «Бросать базу или чистить», «Chaos после фрактура», «Эссенция вместо Exalted», «Эссенции: риск или Whittling»,
   «Десекрейт», «Кость вместо Exalted», «Уточняю лучшие». Этапы с ≥8 вариантами — в 2 прохода (отсев ×1.8).
5. `sim_final` лучшего: 8 000–20 000 прогонов, пока 95% интервал средней не станет ±2%.
6. `putref_vs` — сравнение с Putrefaction; обычный крафт планируется всегда (Putrefaction не может «перебить» его
   без полного расчёта).
`score()` — средняя с поправкой на долю доведённых крафтов; `fscore()` — для фрактура (стоимость / ожидаемое число
удачных фрактуров). `CAP` — лимит действий на крафт; недоделанные входят в среднюю с уже потраченным.

## Механики, которые смоделированы (кратко; подробно для пользователя — README)
- Синий: 1+1; редкий: 3+3 (`gamedata.AFFIX_MAX`), Serle's Triumph +1 суффикс; один крафт-мод (Astrid's +1);
  один десекрейт-мод; одна группа — один мод.
  Если на предмете уже стоит нужный десекрейт-мод (кость дала другой мод из набора), мод, запланированный под десекрейт,
  добивается Exalted (`des_full` в `run`), второй кости при живом десекрейт-моде не бывает.
  Эссенция вместо Regal (`to_rare`) — тоже крафт-мод: только если с запланированными Alloy/эссенциями остаётся место
  (`crafted + pending < max_c`). Стратегия `pbone`: слот «под замену» крафт-модом — костью (нужный вариант остаётся,
  мусор заменит крафт-мод, Omen of Light не нужен). При промахе фрактура на «моём предмете» берётся ещё такой же
  предмет по цене из поля (`again_item`).
  Порядок крафт-модов `cw`: `pre` — все крафт-моды сначала на дешёвый мусор (иначе позже Alloy + Crystallisation
  заменит случайный мод стороны — и найденный нужный); `abyss` — крафт-мод стороны, где ловится мод костью, ставится
  после него: пока на стороне нет крафт-модов, промах кости снимает Essence of the Abyss + Crystallisation (Mark, его
  заменит следующая кость) вместо Annul + Omen of Light; перед этим крафт-модом — один мусор под замену (риск 1 из 2,
  промах оставляет слот под кость). Mark — крафт-мод: цикл только при свободном месте (или Astrid ещё не куплен), пока
  Mark на предмете — крафт-моды ждут. Этап «Кость вместо Exalted» перебирает `cw` pre/abyss и `light` True/abyss.
- Fracturing Orb: ≥4 мода (или 3 + нераскрытая кость, кость не фрактурится); фрактур «не того» нужного мода —
  роли меняются, если он не легче.
- Эссенции: магические (синий → редкий вместо Regal), Perfect/corrupted (заменяют случайный мод; омен
  Crystallisation — только своей стороны и только если там есть мод; иначе сначала Exalted под замену).
  Alloy — так же. Порядок крафт-модов подбирается, чтобы омен снимал мусор, а не уже поставленный крафт-мод.
- Десекрейт: кость (Rib/Jawbone/Collarbone по классу, `gamedata.bone_kind`), Necromancy-омен стороны, раскрытие —
  3 варианта из пула десекрейта (+ моды лордов с оменами лордов на оружии/бижутерии; Otherworldly — Altered
  Collarbone), Abyssal Echoes перекидывает, Omen of Light снимает только десекрейт-мод.
- Essence of the Abyss (правило от пользователя, 23.11): с Crystallisation-оменом стороны заменяет случайный мод этой
  стороны на Mark of the Abyssal Lord (крафт-мод, `M.g == ABYSS_MARK`); следующая кость (любая, без Necromancy и без
  свободного слота) превращает Mark в нераскрытый десекрейт. Используется для снятия неудачного десекрейта, если на его
  стороне кроме него только мусор; Mark рядом с другим крафт-модом требует Astrid's Creativity (покупается один раз,
  `Sim.astrid`). Перчатки: по PoB `socketLimit = 3`, Kolr's Hunt + Astrid's помещаются.
- Качество бижутерии до 40%: Essence of the Breach + каталисты (`gamedata.CATALYST` по тегам модов), затем
  крафт-мод заменяет Breach-мод.
- Omen of Putrefaction: 3 префикса + 3 суффикса нераскрытых, выбор 1 из 3 каждый, предмет corrupted. **Механика из
  описаний, не из файлов игры** — пользователя предупреждали.
- Лимиты аффиксов базы из импликитов (Absent Amulet: 2+2), катализаторное масштабирование значений при разборе.

## Вывод
- `summarize()` — гайд: шаги с расходом, шанс попытки, число попыток; шаги из разных веток объединены
  (`merge_variants`, «не всегда: в ≈N% крафтов»). `chances()` — таблица «Цели». `describe()` — текст стратегии
  (в UI сейчас не показывается, но используется для сравнения вариантов).
- Итоговый гайд на странице сжат по этапам (`crPhases`/`crPhase` в index.html): все «Добавить «X»: <способ>» —
  одна строка «Добивать недостающие моды» (моды списком, вся валюта, короткое правило, когда какой омен/кость),
  все «Убрать мусор…» — одна, десекрейт вместе с «Убрать неудачный десекрейт», «Раскрыть кость…» — одна.
  Строки до фрактура (на одну попытку) и после не смешиваются. Точный выбор на каждом шаге — пошаговый режим.
  `crJoinCraft`: «Добавить префикс/суффикс под замену» сливается со строкой своего крафт-мода («сначала / затем»).
  Каждая строка разбирается `crGuideCell`: короткий заголовок, рамка «Нужный мод / Нужен любой из» (моды из «…» с
  пометкой преф/суф) и рамка «Орбы» (валюта по порядку применения с количеством, «промах», варианты «в ≈N% крафтов»).
  Отдельной колонки расхода нет — количество в рамке. Валюта, не названная в тексте (омен стороны кости), дописывается
  в основную строку. Покупка базы с рунами (Kolr's Hunt) — отдельная строка «Новая база» (`white("Новая база")`).
  Редкие ветки «в ≈N% крафтов: другой омен…» сворачиваются в одну строку «иногда» (каждый орб один раз, без пояснений).
  Мод, выбранный из группы «N из», в рамке показан вместе с заменами: `summarize()` отдаёт `alias` =
  `guide_alias(ctx)` — {текст цели: {nat: моды пула той же стороны, des: те, что бывают на кости}} из `Ctx.alias_of`
  (планировщик и так засчитывает их вместо выбранного). Для «Десекрейт» берётся `des`, для Добавить/Chaos/Поймать — `nat`.
  Подряд идущие «Новая база / Синий предмет / Сделать редким» сливаются в одну строку «Подготовка базы» (`crPrep`,
  орбы по порядку применения, пометка «ничего не ловим»). Рамки — по ширине содержимого; шанс/попытки/div — по центру строки.
- Пошаговый режим: `step_mode(ctx, v, answers)` → следующий вопрос/инфо/вид предмета; `/api/craft/step`.
  Циклы «повторять до результата» (`ask_until`) не задают отдельного «Получилось»: цикл откладывается в
  `self._loop` и показывается вместе со следующим вопросом (`ask` отдаёт `loop` = текст цели цикла). «Получилось»
  остаётся, только если выбирать нечего (у следующего вопроса один вариант) или вопроса нет (`_flush_loop` перед
  следующим `pay`).
  Правило пользователя: не задавать вопрос, ответ на который уже следует из цели или предыдущего ответа.

## Сверка с трейдом (`server.run_craft_trade`)
1. Цели → строки статов трейда (`_tier_lines`, локальные статы `(local)`), одинаковые статы сливаются.
2. Запрос: взвешенная группа (нужен POESESSID; без него — «too complex» → простой запрос) + `and` минимумов
   (90% нижней границы тира, целые — вверх) + по фильтру `count` на группу Count. В группе Count гибридный мод
   представлен строкой, которой нет у других членов, общий стат — одним фильтром. Псевдо-цели — псевдо-статом.
3. **Проверка найденного** (`verify`): из `explicitMods[].mods[]` (имя, тир, уровень) собираются настоящие моды
   предмета (гибрид = один мод на двух строках) и сопоставляются целям (двудольное сопоставление); проверяются
   «И» и каждая группа Count. Самые дешёвые проверяются пачками по 10, пока не найдётся 5 подходящих (до 60).
4. Нет 5 объявлений на этой базе — поиск по всем базам класса (`gamedata.TRADE_CAT`).

## Куда добавлять новое (например, перековку 1.0)
- Новая валюта/омен — `gamedata.py` (название как на poe.ninja) + `NINJA_TYPES`, если новый раздел ninja.
- Новое действие над предметом — метод `Sim` (как `exalt`, `fix`, `bone`, `reveal`), вызов из `run()` под новым
  ключом стратегии; этап перебора в `_plan` (по образцу «Кость вместо Exalted»: `sim_many` по вариантам ключа,
  `res = sorted(res2 + res, key=score)`); текст в `describe()`; вопросы пошагового режима — через `self.ask()`.
- «Закрепить моды» (перековка → фрактур-моды) логически ближе всего к фрактуру: `first_phase()` / `fmode`.
