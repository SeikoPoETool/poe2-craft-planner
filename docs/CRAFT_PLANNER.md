# Планировщик крафта (`craft.py`)

Задача: по цели (какие моды, какого тира, какие обязательны, какие «N из группы») найти последовательность действий
с наименьшей **средней** стоимостью в divine по ценам poe.ninja, показать её гайдом и вести игрока пошагово.
Всё случайное разыгрывается Монте-Карло — тысячи виртуальных крафтов на стратегию.

## Поток данных
```
POST /api/craft (server.run_craft)
  ├─ worker craftData(base, ilvl)       → пул модов, пул десекрейта, Marksman, моды лордов, эссенции, Alloy, импликиты
  ├─ craft_ninja(league)                → цены (div) и иконки
  ├─ expand_pseudo()                    → псевдо-цели («total res ≥ 75», «2 пустых префикса») в обычные
  ├─ Problem(cd, targets, prices, …)    → нормализованная цель: моды, группы Count, лимиты аффиксов
  └─ plan_auto(prob) → summarize() + chances() → JSON для страницы
```

## Сущности
- **`Pool`** — веса модов одной стороны для «пола» уровня (Greater/Perfect валюта катает моды уровня не ниже порога,
  таблица `gamedata.FLOOR`). `W(group, side, floor, minLevel)` — вес нужного тира, `T(side, floor)` — сумма.
  Веса — `engine/mod_weights.json` (poe2db); моду без веса — средний вес тира того же ранга; ручные — `gamedata.WEIGHT_OVERRIDE`.
- **`M`** — мод на предмете: сторона, группа, номер цели (−1 = мусор), флаги `fr` фрактур, `cr` крафт, `de` десекрейт,
  `un` нераскрытая кость, `lv` уровень тира. **`It`** — предмет: список `M` и редкость.
- **`Problem`** — цель пользователя:
  - `assignments()` — варианты ролей: какой мод десекрейтить, какой фрактурить (3 самых редких), какие делать
    эссенцией/Alloy;
  - `subsets()` — для групп Count: конкретные наборы по разбиениям префикс/суффикс; любой мод группы той же стороны
    засчитывается вместо выбранного (`Ctx.pool_alias`);
  - `ctx(a)` — собрать `Ctx` под распределение ролей.
- **`Ctx`** — всё для симуляции одного распределения: цели с источником (`natural` / `desecrated` / `essence` / `alloy`),
  пулы, цены, лимиты, руны; `tval(t)` — во что обойдётся вернуть мод, если его снимет чистка.
- **`Sim`** — один виртуальный крафт по стратегии `v`. `run()` — главный цикл, `pay()` — учёт валюты по шагам.
  В пошаговом режиме (`ia=True`) случайные исходы заменяются вопросами игроку (`ask()`), крафт переигрывается
  с начала с накопленными ответами.

## Стратегия `v` (ключи)
| Ключ | Смысл |
|---|---|
| `first`, `fget`, `fmode` | какой мод ловить первым на синем и как (`chaos`, Transmute/Augment `""`/Greater/Perfect, `annul:<q>` — одна база + Annul); фрактур: `four` (4 мода), `bone` (3 мода + нераскрытая кость), `none` |
| `facc`, `keep` | что принимать на первом шаге; оставлять ли синий с двумя нужными модами |
| `restart` | новая база вместо чистки, пока нужных модов меньше `k` |
| `slam`, `greater` | какой Exalted, Omen of Greater Exaltation |
| `fix` | чистка: `plain` Annul, `omen` Annul + омен стороны, `value` — что дешевле с учётом риска, `whittle` |
| `cw` | когда ставить крафт-моды: `first`, `junk`, `gamble`, `last`, `pre` (все сначала на дешёвый мусор), `abyss` (крафт-мод стороны, где мод ловится костью, — после него, чтобы промах кости снимала Essence of the Abyss) |
| `cslam`, `chard`, `ctrim` | Chaos вместо Exalted после фрактура (качество Chaos, только самый редкий, сначала Annul до одного мусора) |
| `wfix` | перед рискованным крафт-модом снять мусор Chaos + Omen of Whittling (только если на другой стороне есть место) |
| `ftrim` | Chaos-спам первого мода на редком, сначала Annul до одного мода |
| `crepair` | недостающий мод, когда из нужного остались только фрактур/крафт-моды, — Chaos-спам вместо Annul + Exalted |
| `nodyn` | запретить замену слэмов на Perfect/corrupted эссенцию |
| `dslam` | кость вместо Exalted для самого редкого недостающего мода: `once` (промах → дальше Exalted) или `light` (промах снять, кость снова) |
| `pbone` | слот «под замену» крафт-модом — костью: нужный вариант остаётся, мусор заменит крафт-мод |
| `bone`, `echoes`, `light` | кость Preserved/Ancient, Abyssal Echoes; неудачный десекрейт снимать: Annul + Omen of Light, обычный Annul или `abyss` (Essence of the Abyss + Crystallisation) |
| `putref`, `echo` | Omen of Putrefaction (вся база → 6 нераскрытых), политика Echoes |

## Перебор (`plan_auto` → `plan` / `_plan`)
1. **Быстрый отбор**: все распределения ролей × 3 пресета (× способы первого мода при фрактуре). Заходы: 3 крафта
   всем → ещё 7 тем, у кого хоть один дошёл → 40 с отсечкой дорогих крафтов → 100 лучшим (не больше двух стратегий
   на распределение).
2. `putref_screen` — грубая оценка Omen of Putrefaction.
3. **Финалисты** (до 4): лидер и лучший вариант каждого другого «семейства» в пределах ×1.6. Семейство = разбиение
   пула + какие моды делает эссенция/Alloy + есть ли фрактур.
4. `plan(template=…)` для каждого финалиста — координатный спуск по этапам: «Как получить первый мод», «Что принимать
   на первом шаге», «Какой Exalted», «Чистка и крафт-моды», «Chaos после фрактура», «Эссенция вместо Exalted»,
   «Десекрейт», «Кость вместо Exalted», «Уточняю лучшие».
5. Точный прогон финалистов: всем по 3000 крафтов, лидеру и тем, кто в пределах 15%, — до ±2% (до 20 000 крафтов).
6. `putref_vs` — сравнение с Putrefaction.

Что ускоряет перебор:
- до симуляции отбрасывается заведомо проигрышное: Abyssal Echoes всегда, если омен дешёвый (`_echo_opts`); цикл
  Essence of the Abyss — только при свободном месте под крафт-мод (`_abyss_ok`); grade Exalted/Chaos и качество
  кости — в пределах ×2.5 от лучшей цены за попадание (`_slam_grades`, `_chaos_grades`, `_bone_grades`);
- `simulate(early=True)` бросает вариант, если доведено мало крафтов или медиана больше ×2.5 лучшей цены;
- `sim_many` режет крафты дороже ×8 (`CAPK`) лучшей найденной цены; финалисты 2–4 сравниваются с уже посчитанными;
- «Уточняю лучшие» — только варианты в пределах ×2 лидера, в два прохода.

`score()` — средняя с поправкой на долю доведённых крафтов; `fscore()` — для фрактура (стоимость на один удачный
фрактур). `CAP` — лимит действий на крафт; недоделанные входят в среднюю с уже потраченным.

## Механики
- Синий: 1+1; редкий: 3+3 (`gamedata.AFFIX_MAX`), Serle's Triumph +1 суффикс; один крафт-мод (Astrid's Creativity +1);
  один десекрейт-мод на предмете; одна группа — один мод.
- Fracturing Orb: ≥4 мода или 3 + нераскрытая кость (кость не фрактурится). Закрепился другой нужный мод, не легче
  запланированного, — роли меняются. На «моём предмете» промах фрактура = ещё один такой же предмет по цене из поля.
- Эссенции: магические (синий → редкий вместо Regal) и Perfect/corrupted (заменяют случайный мод). Эссенция — тоже
  крафт-мод, поэтому ставится, только если с запланированными Alloy остаётся место. Alloy — как Perfect-эссенция.
  Омен Crystallisation снимает мод только своей стороны и только если он там есть — иначе сначала Exalted под замену.
- Десекрейт: кость по классу (`gamedata.bone_kind`), Necromancy-омен стороны; раскрытие — 3 варианта из пула
  десекрейта (+ моды лордов на оружии и бижутерии), Abyssal Echoes перекидывает, Omen of Light снимает только
  десекрейт-мод.
- Essence of the Abyss + Crystallisation стороны заменяет мод на Mark of the Abyssal Lord (крафт-мод); следующая кость
  превращает Mark в нераскрытый десекрейт. Используется, чтобы снять неудачный десекрейт, когда на его стороне
  кроме него только мусор.
- Качество бижутерии до 40%: Essence of the Breach + каталисты (`gamedata.CATALYST`), затем крафт-мод заменяет Breach-мод.
- Omen of Putrefaction: 3+3 нераскрытых, выбор 1 из 3 каждый, предмет corrupted. **Механика из описаний, а не из
  файлов игры.**

## Вывод
- `summarize()` — шаги с расходом, шансом попытки и числом попыток; ветки объединяются («в ≈N% крафтов»).
  `chances()` — таблица «Цели». `describe()` — текст стратегии (для сравнения вариантов).
- Страница сжимает гайд по этапам (`crPhases` в index.html): все «Добавить «X»» — одна строка «Добивать недостающие
  моды», чистка — одна, десекрейт вместе со снятием неудачного. Каждая строка (`crGuideCell`) — заголовок, рамка
  «Нужный мод / Нужен любой из» и рамка «Орбы». Текстовые пояснения, повторяющие рамки, не пишутся.
- Пошаговый режим: `step_mode(ctx, v, answers)` → следующий вопрос; `/api/craft/step`. Вопрос, ответ на который уже
  следует из цели или прошлого ответа, не задаётся.

## Сверка с трейдом (`server.run_craft_trade`)
1. Цели → строки статов трейда; одинаковые статы сливаются, локальные — `(local)`.
2. Запрос: взвешенная группа + минимумы (90% нижней границы тира) + `count` на каждую группу Count.
3. Найденное проверяется по настоящим модам предмета (`explicitMods[].mods[]`: имя, тир, уровень; гибрид — один мод
   на двух строках). Проверяются пачками по 10, пока не найдётся 5 подходящих (до 60).
4. Меньше 5 объявлений на этой базе — поиск по всем базам класса.

## Куда добавлять новое
- Новая валюта или омен — `gamedata.py` (название как на poe.ninja) и `NINJA_TYPES`, если это новый раздел ninja.
- Новое действие над предметом — метод `Sim` (как `exalt`, `fix`, `bone`, `reveal`), вызов из `run()` под новым
  ключом стратегии, этап перебора в `_plan` (по образцу «Кость вместо Exalted»), текст в `describe()`, вопросы
  пошагового режима — через `self.ask()`.
- Проверка: `python3 tests/regress.py` до и после; новая механика — новый крафт в `tests/cases/`.
