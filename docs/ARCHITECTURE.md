# Архитектура

```
браузер (static/index.html, ванильный JS)
   │  fetch /api/*  (только с той же страницы: проверка Origin/Referer; сервер слушает 127.0.0.1)
   ▼
server.py  (http.server, потоки; задания JOBS в памяти)
   ├── PoB-воркер: engine/luajit + engine/worker.lua, cwd = engine/pob2/src, JSON по stdin/stdout
   ├── craft.py   (импортируется; тяжёлые расчёты — ProcessPoolExecutor на все ядра)
   ├── gamedata.py (правила/названия игры, общие для craft.py и server.py)
   └── внешние: pathofexile.com/api/trade2 (поиск/fetch), poe.ninja (цены, иконки),
                assets.pobb.in (картинки предметов), web.poecdn.com (иконки баз через трейд)
```

## Сервер (`server.py`)
- **Worker** — один процесс LuaJIT с загруженным PoB. Протокол: строка JSON на вход, ответ — строка `@@{json}`;
  строки `%%{json}` — прогресс. Вызовы сериализованы локом. Если процесс упал, при следующем вызове он
  перезапускается и восстанавливает состояние (последний билд, основной скилл, правки конфига).
- **Задания** (`JOBS`): долгие операции (поиск на трейде, скан слотов, джевелы, крафт, сверка крафта с трейдом)
  запускаются в потоке, клиент опрашивает `GET /api/job/<id>`, отмена — `POST /api/cancel`. Новый крафт
  отменяет незаконченный предыдущий. Старые задания чистит `cleanup_jobs()` (крафт живёт сутки: пошаговый режим
  использует его контекст).
- **Трейд**: `trade_call()` — кэш одинаковых запросов (5–10 мин), `RateLimiter` читает заголовки
  `X-Rate-Limit-*` и ждёт сам, на 429 — `Retry-After`. Подробности и грабли — `docs/TRADE_AND_DATA.md`.
- **poe.ninja**: `craft_ninja()` — цены валюты лиги (типы `gamedata.NINJA_TYPES`), проверка на выбросы
  (цена против объёма торгов), иконки. `rates()` — курсы для перевода цен трейда в divine.
- **Ссылки на крафт**: `cache/craft_links.json`, код = sha1 состояния (8 символов). Состояние = база, ilvl, режим,
  текст предмета, цели с тирами, группы Count, цена базы, стартовый предмет.

### API (все POST принимают JSON)
| Метод | Что делает |
|---|---|
| `GET /` , `/bg.webp`, `/img/<name>` | страница, фон (если есть `static/bg.webp`), картинки предметов (кэш `cache/img`) |
| `GET /api/leagues`, `/api/stats`, `/api/craft/bases` | лиги трейда, статы трейда, список баз для крафта |
| `GET /api/job/<id>` | статус/лог/результат задания |
| `GET /api/craft/link/<код>` | сохранённая цель крафта |
| `POST /api/load` | загрузить билд (код pobb.in/PoB) в воркер |
| `POST /api/main` | выбрать основной скилл |
| `POST /api/compare` | «Примерить»: предмет против надетого |
| `POST /api/parse` | разобрать текст предмета (Ctrl+C) |
| `POST /api/export` | код билда для PoB с изменённым конфигом |
| `POST /api/config`, `/api/config/view`, `/api/config/auto`, `/api/config/try` | вкладка «Конфиг» |
| `POST /api/search`, `/api/scan`, `/api/jewels` | поиск замены по слоту, «что улучшать первым», джевелы (задания) |
| `POST /api/plan` | план покупок под бюджет по результатам скана |
| `POST /api/craft/parse` | разобрать предмет для крафта: база, моды, тиры, качество, карточка базы |
| `POST /api/craft` | расчёт крафта (задание) |
| `POST /api/craft/step` | пошаговый режим: ответы игрока → следующий вопрос |
| `POST /api/craft/trade` | сверка цели крафта с трейдом (задание) |
| `POST /api/craft/link` | сохранить цель → код ссылки |
| `POST /api/cancel` | отменить задание |

Пока идёт поиск на трейде, `/api/load`, `/api/main`, `/api/config` запрещены (`MUTATING`): иначе часть кандидатов
посчиталась бы против другого билда. Запросы, которым нужен билд (`NEED_BUILD`), после перезапуска сервера получают
ответ с кодом `NO_BUILD` — страница сама отправляет сохранённый билд, основной скилл и правки конфига и повторяет запрос.

## PoB-воркер (`engine/worker.lua`)
Команды (`cmd.op`): `load`, `setmain`, `info`, `compare`, `parse`, `weights` (веса модов слота — как
TradeQueryGenerator PoB), `eval` (пересчёт кандидатов с трейда), `uniqueJewels`, `evalCombo` (несколько предметов
сразу — план покупок), `setConfig`/`configView`/`configTry`/`configAuto`, `export`, `craftData` (пул модов базы,
тиры, эссенции, моды лордов/десекрейта, импликиты, лимиты аффиксов — всё для `craft.py`).
`HEUR_RULES` — оценка «косвенных» модов, которые PoB считает как 0 (скорость снарядов, Cast on Dodge, Archon…):
«≈ N% DPS» по правилу, с пометкой «низк./средн. увер.».
Воркер запускается с `cwd = engine/pob2/src` и `boot_lib.lua` (загрузчик без BOM/шебанга + HeadlessWrapper PoB).

## Фронтенд (`static/index.html`)
Один файл: CSS (переменные темы в `:root`), разметка вкладок, JS. Без сборки и зависимостей.
- Вкладки: Предметы (кукла), Гемы, Конфиг, Поиск замены, Джевелы, Крафт. Без загруженного билда видна только «Крафт».
- Хелперы: `$` (querySelector), `api()` (fetch + JSON, повтор после `NO_BUILD`), `esc()` (экранирование + «или выше»
  как «≥»), `toast()`, `loader()` (индикатор загрузки с текущим этапом задания), `combo()` (выпадающий список в стиле
  трейда для любого поля выбора).
- Стиль: карточки `.card > .ch` (золотая полоса-заголовок), переключатели `label.tgl`, моды-плашки.
- Крафт: `CR` — состояние вкладки; `renderCrTargets()` — блок «И» и группы Count; `crCombo()` — выпадающий
  список модов в стиле трейда; `renderCraft()` — результат; `crTrade()` — сверка с трейдом; пошаговый режим —
  `#crStep`. Ссылка на крафт — `#craft=<код>` в адресе.

## Данные
- `engine/pob2` — клон PathOfBuilding-PoE2 (`git pull` для обновления). Пулы модов, тиры, эссенции — оттуда.
- `engine/mod_weights.json` — веса выпадения модов по страницам poe2db (`Helmets_int`, `Amulets`…).
- `engine/alloys.json` — Alloy → мод PoB по классу предмета.
  Оба пересобираются `python3 tools/update_poe2db.py` (сначала превью `*.new.json`, затем `--apply`).
- `cache/` — можно удалить всё, **кроме `craft_links.json`** (ссылки пользователя).
